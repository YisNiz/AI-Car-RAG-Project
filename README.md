# מערכת RAG לחברת הרכב "אופק רכב"

מערכת שעונה על שאלות של לקוחות מתוך המסמכים של חברת רכב: מפרט טכני לכל דגם, מחירון, אחריות, טיפולים, קודי התרעה וקריאות שירות. החברה והנתונים דמיוניים, ונכתבו לצורך התרגיל.

הפרויקט התחיל ממערכת שעבדה, אבל ענתה נכון רק על חלק מהשאלות. בכל שלב מדדתי את המערכת, אבחנתי למה היא נכשלת, תיקנתי בעיה אחת ומדדתי שוב.

## התוצאה

| גרסה | מה נוסף | recall@3 | MRR |
|---|---|:---:|:---:|
| בסיס | חיתוך כל 350 תווים, חיפוש לפי משמעות | 6/13 | 0.37 |
| חיתוך | קטע אחד לכל כותרת, עם שם המסמך והכותרת | 9/13 | 0.65 |
| היברידי | חיפוש לפי משמעות יחד עם חיפוש לפי מילים (BM25), מאוחדים ב־RRF | 9/13 | 0.69 |
| מטא־דאטה | סינון מסמכים שהוחלפו בגרסה חדשה | **11/13** | **0.76** |

תשובות Claude עם ציטוטים מאומתים: **13 מתוך 15**, בעלות של פחות מחצי סנט להרצה.

- **recall@3**: בכמה שאלות הקטע הנכון נמצא בין שלושת הקטעים הראשונים.
- **MRR**: כמה גבוה ברשימה נמצא הקטע הנכון (1 = תמיד במקום הראשון).

את הניתוח המלא, כולל טבלת האבחון והתוצאות לפי סוג שאלה, אפשר למצוא ב־[REPORT.md](REPORT.md).

## איך המערכת עובדת

```
מסמכים  →  חיתוך לקטעים  →  וקטורים  →  חיפוש  →  Claude  →  תשובה עם ציטוטים
```

1. **טעינה** (`rag/loader.py`): קריאת המסמכים מתיקיית `data`, יחד עם המטא־דאטה שבראש כל מסמך.
2. **חיתוך** (`rag/chunking.py`): פירוק כל מסמך לקטעים קטנים.
3. **וקטורים** (`rag/embed.py`): הפיכת כל קטע לווקטור שמייצג את המשמעות שלו. המודל הוא `multilingual-e5-small`, שרץ על המחשב ותומך בעברית.
4. **חיפוש** (`rag/search.py`): מציאת שלושת הקטעים הכי רלוונטיים לשאלה.
5. **תשובה** (`rag/answer.py`): שליחת השאלה והקטעים ל־Claude, וקבלת תשובה עם ציטוט מדויק לכל טענה.

## מה כתבתי

| שלב | פונקציה | מה היא עושה | איזו בעיה היא פותרת |
|:---:|---|---|---|
| 3 | `chunk_by_headings` | חותכת כל מסמך לפי כותרות `##`, ובראש כל קטע כותבת את שם המסמך והכותרת | טבלאות שנקרעו באמצע, וקטעים שאיבדו את שם הדגם |
| 4 | `rrf` | מאחדת את תוצאות החיפוש לפי משמעות ואת תוצאות החיפוש לפי מילים, לפי המקום של כל קטע בכל רשימה | קודים כמו `RC-2025-07` ו־`OF-450H`, שהחיפוש לפי משמעות לא מבחין ביניהם |
| 5 | `is_current` | מסננת קטעים ממסמכים שהמטא־דאטה שלהם מסומנת `status: superseded` | מסמך אחריות ישן שסתר את המסמך העדכני |
| 6 | `verify_citations` | בודקת שכל ציטוט של Claude באמת מופיע, מילה במילה, בקטע שהוא מפנה אליו (אחרי נרמול של רווחים ושורות) | ציטוטים מומצאים |

## מה למדתי

- **קודם מודדים ומאבחנים, ורק אחר כך מתקנים.** כל כשל שייך לסוג אחר של בעיה, וכל סוג דורש תיקון אחר.
- **לכל שיפור יש מחיר.** החיתוך לפי כותרות פגע בשאלה שדורשת שני מקורות. החיפוש לפי מילים פגע בשאלה שבה המילה מופיעה עם תחילית בעברית ("לטיפול" מול "טיפול").
- **לא כל כשל מתקנים בחיפוש.** המסמך של הרכב המסחרי הוא PDF סרוק שהטקסט שלו לא חולץ. המערכת עונה בצדק "אין מספיק מידע", ותיקון אמיתי דורש OCR.
- **מסמכים יכולים להכיל הוראות מוסתרות למודל.** באחד המסמכים מוסתרת בתוך הערת HTML הוראה למודל. Claude לא ציית לה, אבל אי אפשר לסמוך על זה, ולכן כדאי לנקות את הקטעים ולהבהיר בהנחיות שהם מידע ולא הוראות.

## התקנה והרצה

נדרש Python 3.10 ומעלה.

```
pip install -r requirements.txt
```

מדידת החיפוש (חינם, בלי Claude):

```
python eval_retrieval.py                                                  # בסיס
python eval_retrieval.py --chunker headings                               # חיתוך
python eval_retrieval.py --chunker headings --mode hybrid                 # היברידי
python eval_retrieval.py --chunker headings --mode hybrid --current-only  # מטא־דאטה
python eval_retrieval.py --show 7                                         # הקטעים שחזרו לשאלה 7
```

מדידת התשובות (בערך סנט אחד, עם `claude-haiku-5-5`). קודם מגדירים את המפתח, רק בטרמינל:

```
$env:ANTHROPIC_API_KEY = "..."      # Windows
export ANTHROPIC_API_KEY="..."      # Mac / Linux
python eval_answers.py --chunker headings --mode hybrid --current-only
```

בהרצה הראשונה עם `--chunker headings`, מודל הווקטורים יורד למחשב, וזה לוקח כמה דקות.
