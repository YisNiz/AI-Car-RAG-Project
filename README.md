# מערכת RAG לחברת הרכב "אופק רכב"

## על הפרויקט

"אופק רכב" היא חברת רכב דמיונית שרוצה מערכת שעונה על שאלות של לקוחות מתוך המסמכים שלה: מפרט טכני לכל דגם, מחירון, קטלוג אביזרים, אחריות, טיפולים, קודי התרעה וקריאות שירות.

המערכת בנויה בשיטת **RAG** (Retrieval-Augmented Generation). כשלקוח שואל שאלה, המערכת קודם **מחפשת** במסמכים את הקטעים הרלוונטיים, ורק אחר כך שולחת אותם ל־**Claude**, שעונה מתוכם בלבד ומצרף ציטוט מדויק לכל טענה.

```
מסמכים  →  חיתוך לקטעים  →  וקטורים  →  חיפוש  →  Claude  →  תשובה עם ציטוטים
```

בתחילת הפרויקט קיבלתי מערכת שעבדה, אבל מצאה את הקטע הנכון רק ב־6 מתוך 13 שאלות. התפקיד שלי היה למדוד אותה, להבין למה היא נכשלת, ולשפר אותה שלב אחרי שלב.

## התוצאה

| גרסה | מה נוסף | recall@3 | MRR |
|---|---|:---:|:---:|
| בסיס | חיתוך כל 350 תווים, חיפוש לפי משמעות | 6/13 | 0.37 |
| חיתוך | קטע אחד לכל כותרת, עם שם המסמך והכותרת | 9/13 | 0.65 |
| היברידי | חיפוש לפי משמעות יחד עם חיפוש לפי מילים (BM25), מאוחדים ב־RRF | 9/13 | 0.69 |
| מטא־דאטה | סינון מסמכים שהוחלפו בגרסה חדשה | **11/13** | **0.76** |

תשובות Claude עם ציטוטים מאומתים: **13 מתוך 15**, בעלות של פחות מחצי סנט להרצה.

- **recall@3**: בכמה שאלות הקטע הנכון נמצא בין שלושת הקטעים הראשונים.
- **MRR**: כמה גבוה ברשימה נמצא הקטע הנכון (1 = תמיד במקום הראשון).

## החלק שלי

### 1. מדידה ואבחון

הרצתי את המערכת על 15 שאלות בדיקה. לכל שאלה שנכשלה בדקתי אילו קטעים חזרו, חיפשתי את התשובה במסמך המקורי, וסיווגתי את סוג הבעיה:

| שאלה | הבעיה שמצאתי | סוג |
|:---:|---|:---:|
| 2 | החיפוש לפי משמעות לא מבחין בין `OF-450H` לבין `OF-450` | מילים |
| 3 | החיפוש לא מבחין בין קריאת השירות `RC-2025-07` לקריאות דומות | מילים |
| 5 | המסמך של הרכב המסחרי הוא PDF סרוק, והטקסט שלו לא חולץ, אז נשארה בו רק כותרת | מלאי |
| 6 | שורת קוד ההתרעה E-31 נמצאת בקטע בלי כותרת המסמך ובלי שורת העמודות | חיתוך |
| 7 | המשפט על שבעה מקומות ישיבה נמצא באותו קטע עם טבלת מנוע, שמטשטשת את המשמעות שלו | חיתוך |
| 10 | החיתוך הפריד את צריכת הדלק (18.5) משם הדגם | חיתוך |
| 11 | חזר גם מסמך אחריות ישן (5 שנים) שסותר את העדכני (7 שנים) | גרסה |

### 2. חיתוך לפי כותרות: `chunk_by_headings`

החלפתי את החיתוך העיוור (כל 350 תווים) בחיתוך לפי כותרות `##`. בראש כל קטע מופיעים שם המסמך והכותרת, למשל "אופק סיטי (OF-210) › מנוע והנעה", כך שכל טבלה נשארת שלמה וכל קטע יודע לאיזה דגם הוא שייך.

**תוצאה:** שאלות 6, 7 ו־10 תוקנו, כמו שחזיתי באבחון, וגם שאלה 2. מנגד, שאלה 12 ("איזה רכב חשמלי נוסע רחוק יותר?") נפגעה, כי טבלאות הטווח של שני הרכבים הפכו לקטעים נפרדים, ושתיהן לא נכנסו יחד לשלושת המקומות הראשונים.

### 3. חיפוש היברידי: `rrf`

כתבתי את Reciprocal Rank Fusion, שמאחד את תוצאות החיפוש לפי משמעות עם תוצאות החיפוש לפי מילים (BM25). כל קטע מקבל ‎1/(60 + המקום שלו) מכל רשימה, וממיינים לפי הסכום.

**תוצאה:** שאלה 3 תוקנה, כי BM25 מוצא את הקוד המדויק. מנגד, שאלה 8 נפגעה: BM25 משווה מילים בדיוק, ולכן "לטיפול" שבשאלה ו"טיפול" שבקטע הן בשבילו מילים שונות. זו בעיה מוכרת בעברית, שבה מוסיפים למילים אותיות כמו ל, ב, ה.

### 4. סינון לפי מטא־דאטה: `is_current`

מצאתי שבמטא־דאטה של מסמך האחריות הישן כתוב `status: superseded`, וכתבתי פונקציה שמוציאה מסמכים כאלה מהתוצאות.

**תוצאה:** שאלה 11 תוקנה. גם שאלה 8 חזרה, למרות שהיא לא קשורה לאחריות: קטע האחריות הישן תפס מקום בתוצאות שלה, ושחרור המקום הכניס את הקטע הנכון לשלושה הראשונים.

### 5. אימות ציטוטים: `verify_citations`

כתבתי פונקציה שבודקת שכל ציטוט של Claude באמת מופיע, מילה במילה, בקטע שהוא מפנה אליו. לפני ההשוואה הפונקציה מנרמלת רווחים וירידות שורה, כדי שציטוט שחוצה שורה לא ייפסל בטעות.

**תוצאה:** 13 מתוך 15 תשובות תקינות. בדקתי שלושה מקרים מיוחדים:
- **שאלות שאין להן תשובה בנתונים:** Claude ענה שאין מספיק מידע, ולא המציא.
- **הרכב המסחרי:** Claude ענה שאין מידע. זה מתאים לאבחון, כי המסמך ריק.
- **הוראה מוסתרת:** מצאתי באחד המסמכים הוראה למודל, מוסתרת בתוך הערת HTML, שמנסה לגרום לו להבטיח הנחה מזויפת ולבקש פרטים אישיים מהלקוח. Claude לא ציית לה.

### 6. דוח

כתבתי את [REPORT.md](REPORT.md), ובו טבלת האבחון, התוצאות לפי סוג שאלה בכל אחת מארבע הגרסאות, וניתוח של מה השתפר, מה נפגע, ומה נשאר שבור.

## מה למדתי

- **קודם מודדים ומאבחנים, ורק אחר כך מתקנים.** כל כשל שייך לסוג אחר של בעיה, וכל סוג דורש תיקון אחר.
- **לכל שיפור יש מחיר.** החיתוך פגע בשאלה שדורשת שני מקורות, והחיפוש לפי מילים פגע בשאלה עם תחילית בעברית.
- **לא כל כשל מתקנים בחיפוש.** את המסמך הסרוק אפשר לתקן רק ב־OCR, כלומר בזיהוי הטקסט מתוך התמונה.
- **מסמכים יכולים להכיל הוראות מוסתרות למודל.** כדאי לנקות את הקטעים, ולהבהיר בהנחיות שהם מידע ולא הוראות.

## התקנה והרצה

נדרש Python 3.10 ומעלה.

```
pip install -r requirements.txt
```

מדידת החיפוש (חינם, בלי Claude):

```
python eval_retrieval.py                                                  # בסיס
python eval_retrieval.py --chunker headings                               # חיתוך
python eval_retrieval.py --chunker headings --mode hybrid                 # היברידי
python eval_retrieval.py --chunker headings --mode hybrid --current-only  # מטא־דאטה
python eval_retrieval.py --show 7                                         # הקטעים שחזרו לשאלה 7
```

מדידת התשובות (בערך סנט אחד, עם `claude-haiku-5-5`). קודם מגדירים את המפתח, רק בטרמינל:

```
$env:ANTHROPIC_API_KEY = "..."      # Windows
export ANTHROPIC_API_KEY="..."      # Mac / Linux
python eval_answers.py --chunker headings --mode hybrid --current-only
```
